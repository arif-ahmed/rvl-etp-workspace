> [← Contents](README.md)

Every `[UNCONFIRMED: Q-nn]` marker in this documentation points to an entry here. An entry means **this review could not settle the question from the code in the five repositories** — not that the code is wrong. Some are gaps in the repository (an external service with no source), some are deployment or configuration values, some are genuine ambiguities in the implementation, and some are cases where the code is unambiguous but the *intent* is not.

Read the **Kind** column before acting on a query. The four kinds are:

| Kind | Meaning | Who can answer |
|---|---|---|
| **External** | The component is not in any of the five repositories | BS23 |
| **Deployment** | The code reads a value from settings, secrets, SSM or the cloud that this review cannot see | BS23 / infrastructure |
| **Ambiguity** | The code is readable but its correctness or intent cannot be judged without knowing the requirement | BS23 / the business |
| **Defect** | The code appears wrong; this is a finding to fix, not a question to answer | RVL |

A **Defect** row is the one to prioritise. The rest are documentation debt.
