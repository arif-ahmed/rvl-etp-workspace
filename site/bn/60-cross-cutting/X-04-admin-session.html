X-04 অ্যাডমিন সেশন ব্যবস্থাপনা (টোকেন সংযুক্তি ও রিফ্রেশ)

Bangla name: অ্যাডমিন সেশন ব্যবস্থাপনা (টোকেন সংযুক্তি ও রিফ্রেশ)

← 60 · ক্রস-কাটিং · সূচিপত্র · ওপেন কোয়ারি

1. নাম ও উদ্দেশ্য

অ্যাডমিন সেশন ব্যবস্থাপনা। ব্যাখ্যা করে যে অ্যাডমিন পোর্টাল কীভাবে প্রতিটি API কলে Cognito অ্যাক্সেস টোকেন ও প্রোগ্রাম id যুক্ত করে, টোকেন মেয়াদ শেষ হওয়ার আগে বা পরে কীভাবে রিফ্রেশ করে, এবং কখন লজ্জা ছেড়ে ইউজারকে লগইন পেজে পাঠায়। প্রতিটি A-xx ফিচার এর উপর নির্ভর করে।

2. ট্রিগার ও অ্যাক্টর

বিষয় মান
অ্যাক্টর অ্যাডমিন পোর্টালের যেকোনো সাইন ইন করা ব্যবহারকারী; পোর্টালের করা প্রতিটি HTTP কল একে ট্রিগার করে
ক্লায়েন্ট অ্যাডমিন পোর্টাল: AuthInterceptor, ProgramIdInterceptor, LoaderInterceptor (app.module.ts-এ রেজিস্টার করা)
Cognito pool Admin
রোল / প্রোগ্রাম স্কোপ প্রতিটি রিকোয়েস্টে X-Program-Id যোগ হয় (X-16)

3. ব্যবসায়িক প্রবাহ

সেশন বৈধ থাকা অবস্থায় ইউজার কিছুই বুঝতে পারেন না। refresh token আর বৈধ না থাকলে (মেয়াদ শেষ, পাসওয়ার্ড রিসেট বা অ্যাকাউন্ট নিষ্ক্রিয় করায় বাতিল), পরের কলটি ব্যর্থ হয়, পোর্টাল সাইন আউট করে এবং লগইন পেজ খোলে।

4. প্রযুক্তিগত প্রবাহ

# ধাপ বিবরণ
১ স্কিপ লিস্ট /admin-users/forget-password, admin/login-2fa-send-otp, admin/login-2fa-verify-otp, /admin-users/set-forget-password ধরা যুক্ত URL পায় না
২ টোকেন নিন CognitoService.getAccessToken(): অ্যাক্সেস টোকেন ৫৫ মিনিটের কম বয়সী হলে এবং তার exp থেকে ২ মিনিটের বেশি বাকি থাকলে ক্যাশ করা টোকেন ফেরত দেয়; নয়তো রিফ্রেশ করে
৩ সংযুক্ত করুন ক্লোন করা রিকোয়েস্টে Authorization: Bearer <access token>
৪ প্রোগ্রাম হেডার ProgramIdInterceptor /admin/login-2fa* ছাড়া প্রতিটি রিকোয়েস্টে X-Program-Id: <localStorage.globalProgramId> যোগ করে। গ্লোবাল মেনুতে মান 0
৫ কল Admin, Booking, Ticketing বা UserIssue-এর কাছে [HTTP + user token]
৬ 401 হলে একবারে একটি রিফ্রেশ (isRefreshing ফ্ল্যাগ + BehaviorSubject): Auth.currentSession() refresh token দিয়ে রিফ্রেশ করে; ব্যর্থ রিকোয়েস্টটি নতুন টোকেন দিয়ে একবার আবার চালানো হয়; ইতিমধ্যে আসা রিকোয়েস্টগুলো তার জন্য অপেক্ষা করে
৭ রিফ্রেশ ব্যর্থ handleRefreshFailure(): ক্যাশ ও lastKnownUserRole মোছে, Auth.signOut(), /auth/login-এ নেভিগেট করে

app.module.ts-এ ইন্টারসেপ্টরের ক্রম: AuthInterceptor, LoaderInterceptor, ProgramIdInterceptor।

ধরন কম্পোনেন্ট

সার্ভিস অ্যাডমিন পোর্টাল যে সব সার্ভিস কল করে; তারা টোকেন যাচাই করে (X-14)

6. API কন্ট্রাক্ট

এটি নিজস্ব এন্ডপয়েন্ট থাকা একটি ফিচার নয়। অ্যাডমিন পোর্টালের প্রতিটি API কলে যুক্ত হেডার:

হেডার মান কে পড়ে
Authorization Bearer <Cognito access token> প্রতিটি সার্ভিসের JWT bearer handler (X-14)
X-Program-Id নির্বাচিত প্রোগ্রাম id, 0 = কোনোটি নয় Admin সার্ভিসের ProgramIdMiddleware ও [AuthorizeProgram] (X-16); অন্য সার্ভিসগুলো উপেক্ষা করে

9. হ্যান্ডওভার নোট

  1. দুটি রিফ্রেশ গার্ড। AuthInterceptor ও CognitoService দুটোই নিজস্ব isRefreshing ফ্ল্যাগ ও সাবজেক্ট রাখে। আজ তারা একসাথে কাজ করে, কিন্তু একটি বদলালে অপরটির কথা মাথায় রাখতে হবে।
  2. SignalR চ্যাট সংযোগ ইন্টারসেপ্টরের বাইরে। এটি টোকেন query string-এ পাঠায় (A-24)।
  3. X-Program-Id প্রতিটি সার্ভিসে যায়। শুধু Admin সার্ভিস এটি পড়ে; Booking, Ticketing ও UserIssue উপেক্ষা করে।
  4. কোনো idle timeout নেই। সেশন চলে যতক্ষণ না Cognito-র refresh token বৈধ (pool সেটিং, রিপোজিটরিতে নেই)।
