X-05 স্টাফ অ্যাকাউন্ট তৈরি

Bangla name: স্টাফ অ্যাকাউন্ট তৈরি

← 60 · ক্রস-কাটিং · সূচিপত্র · ওপেন কোয়ারি

1. নাম ও উদ্দেশ্য

স্টাফ অ্যাকাউন্ট তৈরি। কর্মীরা কখনো নিজেরা সাইন আপ করেন না। একজন অ্যাডমিনিস্ট্রেটর অ্যাডমিন পোর্টাল থেকে প্রতিটি অ্যাডমিন, টিকিট-চেকার ও এজেন্ট অ্যাকাউন্ট তৈরি করেন; এরপর Admin সার্ভিস সরাসরি মিলে যাওয়া Cognito pool-এ ব্যবহারকারী তৈরি করে, একটি জেনারেট করা স্থায়ী পাসওয়ার্ড নির্ধারণ করে, এবং ইউজারনেম ও পাসওয়ার্ড SMS-এ ফোনে পাঠায়। একই সার্ভিস এই অ্যাকাউন্টগুলো নিষ্ক্রিয় করে, সক্রিয় করে, মোছে ও রিসেট করে। এই ফাইলটি যে সাধারণ মেকানিক্স বর্ণনা করে; স্ক্রিনগুলো রয়েছে A-25 (অ্যাডমিন), A-17 (চেকার) ও A-26 (এজেন্ট)।

2. ট্রিগার ও অ্যাক্টর

বিষয় মান
অ্যাক্টর গ্লোবাল মেনুতে (প্রোগ্রাম 0) থাকা অ্যাডমিন-পোর্টাল ব্যবহারকারী। অ্যাডমিন অ্যাকাউন্ট: রোল admin। চেকার অ্যাকাউন্ট: admin, event_manager, ticket_manager, ticket_operator (কন্ট্রোলার রোল)। এজেন্ট অ্যাকাউন্ট: সার্ভার-সাইড কোনো সীমাবদ্ধতা নেই (নোট দেখুন)
ক্লায়েন্ট ও স্ক্রিন অ্যাডমিন পোর্টাল → Users → "Regular Admins" (/users), "Ticket Checkers" (/ticket-checker), "Seller Agents" (/agent-user); মেনু শুধু admin-এর জন্য দেখা যায় (X-17)
যে Cognito pool-এ লেখা হয় Admin, TicketChecker, Agent

3. ব্যবসায়িক প্রবাহ

  1. অ্যাডমিনিস্ট্রেটর নাম, ফোন (ফরমটি +880 যোগ করে), ইমেইল এবং অ্যাডমিনদের ক্ষেত্রে এক বা একাধিক রোল ও ব্যবহারকারী যে প্রোগ্রামগুলোতে কাজ করতে পারবে তা পূরণ করেন।
  2. অ্যাকাউন্ট তৈরি হয় এবং নতুন ব্যবহারকারী একটি SMS পান: "Your account has been created successfully. Your user name is and password is "।
  3. পরে অ্যাডমিনিস্ট্রেটর নাম/রোল/প্রোগ্রাম সম্পাদনা করতে, অ্যাকাউন্ট নিষ্ক্রিয় বা সক্রিয় করতে, মুছতে, বা "Set Password" করতে পারেন, যা নতুন পাসওয়ার্ড জেনারেট করে SMS-এ পাঠায়।
  4. অ্যাকাউন্ট নিষ্ক্রিয় করলে (এবং পাসওয়ার্ড রিসেট করলে) ইউজার প্রতিটি ডিভাইস থেকে সাইন আউট হয়ে যায়।

4. প্রযুক্তিগত প্রবাহ

# থেকে → পর্যন্ত হপ কী ঘটে
১ অ্যাডমিন পোর্টাল → Admin POST /admin/api/v1/admin-users (বা /ticket-checker, /agent-users) [HTTP + user token] নাম, ফোন, ইমেইল, রোল, প্রোগ্রাম id-সহ বডি
২ Admin সার্ভিস → Cognito AWS SDK, static keys AWS:AccessKey / AWS:SecretAccessKey অ্যাডমিন ইউজার: ডুপ্লিকেট ইমেইল প্রত্যাখ্যান করতে ListUsers(email = …); তারপর অস্থায়ী পাসওয়ার্ড দিয়ে AdminCreateUser(Username = phone, attributes), তারপর একই পাসওয়ার্ড দিয়ে AdminSetUserPassword(Permanent = true)
৩ Admin সার্ভিস → Notification সার্ভিস POST /notification/send-message [HTTP, static key] ইউজারনেম ও পাসওয়ার্ডসহ SMS
৪ Admin সার্ভিস → ডেটাবেস — অ্যাক্টিভিটি লগ AdminUser / Created (অ্যাডমিন অ্যাকাউন্টের জন্য) (X-24)
U আপডেট AdminUpdateUserAttributes name, custom:role, custom:program_ids (কোনো প্রোগ্রাম না থাকলে খালি স্ট্রিং), email_verified, phone_number_verified; ক্যাশ করা অ্যাট্রিবিউট user_{id} সরানো হয়
D নিষ্ক্রিয় / সক্রিয় AdminDisableUser / AdminEnableUser + AdminUserGlobalSignOut একজন অ্যাডমিন নিজেকে নিষ্ক্রিয় বা মুছতে পারে না (ArgumentNullException("Invalid permission") → 400)
P পাসওয়ার্ড নির্ধারণ AdminUserGlobalSignOut, AdminSetUserPassword(generated, Permanent), নতুন পাসওয়ার্ডসহ SMS অ্যাডমিন: বডি { userId }; চেকার ও এজেন্ট: query ?userId=
X মুছে ফেলা AdminDeleteUser, ক্যাশ এন্ট্রি সরানো

প্রতি pool-এ লেখা অ্যাট্রিবিউট

Pool ইউজারনেম অ্যাট্রিবিউট
Admin ফোন phone_number, name, email, custom:role (কমা-আলাদা রোল), custom:program_ids (কমা-আলাদা id, ঐচ্ছিক), email_verified=true, phone_number_verified=true
TicketChecker ফোন phone_number, name, email = <phone without +>@gobcbticket.com, custom:role = "TicketChecker"
Agent ফোন phone_number, name, custom:branch_location, custom:company_name, custom:company_branch, phone_number_verified=true, ঐচ্ছিক custom:email

জেনারেট করা পাসওয়ার্ড: ৮ অক্ষর, কমপক্ষে একটি বড় হাতের অক্ষর, ছোট হাতের অক্ষর, সংখ্যা এবং !@#$-এর একটি, System.Random দিয়ে তৈরি (AdminUserProvider.GeneratePassword)।

7. ডেটা ও পার্শ্বপ্রতিক্রিয়া

  • অ্যাকাউন্টের ধরনের pool-এ Cognito ব্যবহারকারী তৈরি, আপডেট, নিষ্ক্রিয়, সক্রিয় বা মোছা হয়।
  • ইউজারনেম ও পাসওয়ার্ডসহ SMS (তৈরি) বা নতুন পাসওয়ার্ডসহ SMS (পাসওয়ার্ড নির্ধারণ)।
  • নিষ্ক্রিয়, সক্রিয় ও পাসওয়ার্ড নির্ধারণের সময় লক্ষ্য ব্যবহারকারীর গ্লোবাল সাইন আউট।
  • অ্যাডমিন অ্যাকাউন্টের জন্য অ্যাক্টিভিটি লগ রো (Created, Updated, Deleted, Disabled, Enabled, PasswordReset)।
  • আপডেট ও ডিলিটের সময় ক্যাশ key user_{userId} সরানো হয়, যাতে সেই সার্ভিস ইনস্ট্যান্সের পরের রিকোয়েস্ট রোল বদল দেখে।

9. হ্যান্ডওভার নোট

  1. এজেন্ট অ্যাকাউন্ট টোকেন ছাড়াই পরিচালনা করা যায়। AgentController-এ কোনো [Authorize] নেই এবং BaseController-এর [Authorize] কমেন্ট করা, তাই কোডে /admin/api/v1/agent-users/* (তৈরি, পাসওয়ার্ড নির্ধারণ, মুছে ফেলা, …) anonymous। গেটওয়ে এটি আটকায় কি না জানা নেই [UNCONFIRMED: Q-04]। X-18 দেখুন।
  2. পাসওয়ার্ড System.Random দিয়ে জেনারেট হয় এবং স্পষ্ট লেখায় SMS-এ পাঠানো হয়। পাসওয়ার্ডটি স্থায়ী হিসেবে নির্ধারণ হয়, তাই প্রথম লগইনে Cognito কখনো ব্যবহারকারীকে সেটি বদলাতে বলে না।
  3. ইমেইলের অনন্যত্ব শুধু অ্যাডমিন অ্যাকাউন্টের জন্য যাচাই হয়; Cognito ইউজারনেম হলো ফোন নম্বর, তাই একটি ফোন একটি pool-এ একবারই থাকতে পারে।
  4. রোল ও প্রোগ্রামের পরিবর্তন সব জায়গায় সঙ্গে সঙ্গে কাজ করে না। Admin সার্ভিস আপডেটের সময় নিজের ক্যাশ থেকে user_{id} মোছে, কিন্তু UserIssue সার্ভিসের অ্যাট্রিবিউট ক্যাশের নিজস্ব কপি আছে (X-15), আর অ্যাডমিন পোর্টাল রোল ৫৫ মিনিট ক্যাশ করে (X-17)। ইতিমধ্যে ইস্যু করা অ্যাক্সেস টোকেন মেয়াদ শেষ না হওয়া পর্যন্ত বৈধ থাকে।
  5. চেকারের custom:role হলো TicketChecker, যা রোল কনস্ট্যান্টগুলোর একটি নয়; চেকারের রোল claim (ticket-checker) আসে টোকেন স্কিম থেকে, এই অ্যাট্রিবিউট থেকে নয় (X-14)।
  6. SMS ব্যর্থ হলে অর্ধেক সম্পন্ন কাজ থেকে যায়। SMS পাঠানোর আগেই Cognito ব্যবহারকারী ও পাসওয়ার্ড তৈরি হয়; Notification সার্ভিস ব্যর্থ হলে অ্যাকাউন্ট থাকা সত্ত্বেও API 400 ফেরত দেয়।
