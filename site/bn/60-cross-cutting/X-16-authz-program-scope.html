X-16 অথরাইজেশন স্তর ৪: প্রোগ্রাম স্কোপ

Bangla name: অথরাইজেশন স্তর ৪: প্রোগ্রাম স্কোপ

← 60 · ক্রস-কাটিং · সূচিপত্র · ওপেন কোয়ারি

1. নাম ও উদ্দেশ্য

প্রোগ্রাম স্কোপ। admin ছাড়া কর্মীরা কেবল তাদের custom:program_ids-এ নিয়োজিত প্রোগ্রামগুলোর (সিরিজ/টুর্নামেন্ট) উপরই কাজ করা উচিত। কোডে X-Program-Id হেডার ব্যবহার করে দুটি আলাদা পদ্ধতি আছে:

  1. একটি ডেটা ফিল্টার: Admin সার্ভিসে একটি EF Core global query filter, যা প্রোগ্রাম-মালিকানাধীন রো-কে হেডারের প্রোগ্রামে সীমাবদ্ধ করে;
  2. একটি অ্যাক্সেস চেক: [AuthorizeProgram], যা হেডারকে ব্যবহারকারীর program_id claim-এর সঙ্গে তুলনা করে, কেবল dashboard-এ ব্যবহৃত।

2. ট্রিগার ও অ্যাক্টর

বিষয় মান
অ্যাক্টর অ্যাডমিন পোর্টাল ব্যবহারকারী, প্রোগ্রাম বেছে নেওয়ার পর (A-01)
ক্লায়েন্ট অ্যাডমিন পোর্টালের ProgramIdInterceptor প্রতিটি request-এ X-Program-Id পাঠায় (X-04)
সার্ভিস শুধু Admin

3. ব্যবসায়িক প্রবাহ

একজন কর্মী একটি প্রোগ্রাম বাছেন; এরপর থেকে তালিকাগুলোতে (events, promo codes, discounts, notices, ticket layouts, …) কেবল ঐ প্রোগ্রামের ডেটা দেখা যায়। "back to global menu" বেছে নিলে প্রোগ্রাম 0 হয়, যা global মেনু দেখায় (X-17)।

4. কারিগরি প্রবাহ

# ধাপ বিবরণ
1 ProgramIdMiddleware X-Program-Id পার্স করে; HttpContext.Items["ProgramId"]-এ রাখে (অনুপস্থিত, সংখ্যা নয় বা ≤ 0 হলে 0)
2 ProgramIdAccessor Scoped service যা Items["ProgramId"] পড়ে
3 AdminDbContext query filter IHasProgramId ইমপ্লিমেন্ট করা প্রতিটি entity-এর জন্য: ProgramId <= 0 OR entity.ProgramId == ProgramId
4 [AuthorizeProgram] (শুধু dashboard) রোল admin → পাস। রোল user → পাস ("portal user … not defined yet")। অন্যথায়: হেডার অনুপস্থিত/অবৈধ/নেতিবাচক → 400 "Missing or invalid X-Program-Id header."; হেডার ব্যবহারকারীর program_id claim-এ না থাকলে → 403 "User does not have permission for program with Id {id}."

যেসব entity ফিল্টার হয় (IHasProgramId): Event, EventVenueDetails, ProgramTeam, ProgramVenue, ProgramVenueDetails, ProgramSettings, PromoCode, PromoCodeAssign, Discount, DiscountAssign, GeneralNotice, TicketCheckerGate, TicketAttributes, TicketLayoutConfig, UserIssue, UserIssueChatMessage।

ধরন কম্পোনেন্ট

সার্ভিস Admin: ProgramIdMiddleware, ProgramIdAccessor, AdminDbContext, AuthorizeProgramAttribute, DashboardController

9. হ্যান্ডওভার নোট

  1. ডেটা ফিল্টার কোনো অ্যাক্সেস কন্ট্রোল নয়। এটি হেডারকে বিশ্বাস করে। প্রোগ্রাম ১-এ সীমাবদ্ধ একজন ব্যবহারকারী X-Program-Id: 2 পাঠালে প্রোগ্রাম ২-এর রো দেখতে পান; 0 (বা কোনো হেডার না পাঠালে) পাঠালে ফিল্টার পুরোপুরি সরে যায়। কেবল dashboard ব্যবহারকারীর প্রোগ্রামের বিপরীতে হেডার যাচাই করে।
  2. 403 শাখা কাজ থামায় না। AuthorizeProgramAttribute 403 রেসপন্স লেখে কিন্তু context.Result সেট করে না; একটি IAsyncAuthorizationFilter-এর ক্ষেত্রে MVC তারপরও এগিয়ে action চালায়, যা ইতিমধ্যে শুরু হয়ে গেছে এমন রেসপন্সে লিখতে গিয়ে ব্যর্থ হয়। dashboard-এর (read-only) ক্ষেত্রে প্রভাব একটি error log, কিন্তু এভাবে লেখার endpoint-এর জন্য এই attribute ব্যবহার করবেন না।
  3. Middleware ও ফিল্টার কেবল Admin সার্ভিসে আছে। Booking, Ticketing ও UserIssue হেডারটি পেয়ে উপেক্ষা করে; তাদের admin endpoint-গুলো বদলে query parameter হিসেবে programId নেয় (যেমন reports, A-22)।
  4. user রোল [AuthorizeProgram] পাস করে, কিন্তু dashboard-এর ক্লাস attribute-এ Admin pool সহ admin বা ticket_operator লাগে, তাই গ্রাহকরা এতে পৌঁছাতে পারে না।
