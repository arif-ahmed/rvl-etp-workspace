X-03 Admin change password and logout

Bangla name: অ্যাডমিন পাসওয়ার্ড পরিবর্তন ও লগআউট

← 60 · Cross-cutting · Contents · Open queries

1. Name and purpose

Change password lets a signed-in staff member replace the password, after which the portal signs out. Logout ends the session in the browser and clears the program selection and the CloudFront cookies. Both run entirely between the browser and Cognito; no GoBCB service is called.

2. Trigger and actor

Item Value
Actor Any signed-in admin-portal user
Client and screen Admin portal top bar → profile menu → "Change Password" (route /change-password, ChangePasswordComponent) and "Logout" (AppTopBarComponent.logout())
Cognito pool Admin
Role / program scope Any role; no program needed

3. Business flow

Change password 1. The user types the current password and the new password twice (new password at least 8 characters, must differ from the old one). 2. On success the portal shows "Your password has been successfully updated.", signs out and opens the login page after one second. 3. If the current password is wrong the message is "Current password is wrong."

Logout 1. The user confirms "Are you sure you want to log out?". 2. The portal signs out of Cognito, resets the selected program to 0 (global menu), expires the three CloudFront-* cookies and opens /auth/login.

4. Technical flow

6. API contracts

No GoBCB endpoint is used. Cognito APIs called through Amplify: ChangePassword, and the token revocation Amplify performs on sign-out.

The backend has a server-side change-password implementation for admins (AdminUserManager.ChangePasswordAsync, which calls Cognito ChangePassword with an access token) but no controller exposes it. The portal's ChangePasswordService calls PUT /admin/api/v1/Users/change-password, which does not exist; that service is not used by the screen. Both are listed in Appendix A.

7. Data and side effects

  • Cognito: password changed. Existing refresh tokens remain valid until they expire or are revoked; the portal only signs out locally.
  • Browser: tokens, caches, program selection and CloudFront cookies removed on logout.

9. Handover notes

  1. Sign-out is local. Amplify's Auth.signOut() without { global: true } does not revoke other sessions. To end every session of a user, an admin must disable the account or reset its password (X-05), which call AdminUserGlobalSignOut.
  2. The program selection survives in localStorage across reloads; logout resets it to 0 so the next user starts in the global menu (A-01).
  3. Cookie clean-up may miss the real cookies. The cookies were written with domain=environment.cloudFront.mainDomain (X-01); clearSignedCookie() expires them without a domain attribute. Browsers treat a cookie set with a Domain attribute and a host-only cookie of the same name as different cookies, so the CloudFront cookies can survive logout until they expire. Check in DevTools → Application → Cookies on a deployed environment.
