X-17 Client-side authorization (menus and guards)

Bangla name: ক্লায়েন্ট-সাইড অথরাইজেশন (মেনু ও গার্ড)

← 60 · Cross-cutting · Contents · Open queries

1. Name and purpose

Client-side authorization. The portals hide menu items and block routes depending on the signed-in user's role and the selected program. This is convenience, not security: anything a route guard blocks can still be called directly on the API, where only the server-side layers count (X-14–X-16).

2. Trigger and actor

Item Value
Actor Admin-portal staff; user-portal customers
Client Admin portal: AppMenuComponent.buildMenu, AuthGuard + RoleChangeService, ProgramMenuGuard, LimitedMenuGuard. User portal: AuthGuard, UnAuthGuard, LanguageGuard

3. Business flow

Admin portal. Two menus exist: the global menu (no program selected, program id 0) and the program menu (a program selected). After login the user lands on the global page for the role (X-01); choosing a program in Program management switches to the program menu (A-01); "back to global menu" sets the program to 0.

User portal. tickets/* and issues/* need a login; auth/* is only for signed-out visitors; user-profile has no guard.

4. Technical flow

Admin portal route guards (app-routing.module.ts):

Guard Routes Rule
ProgramMenuGuard '' (dashboard), events, promo-management, ticket-layout, issues, report Needs program id > 0, else redirect to /program-management
LimitedMenuGuard users, ticket-checker, settings, agent-user, venue-management, program-management Needs program id == 0, else redirect to /
AuthGuard activity-log, home, and inside each feature module Signed in (Auth.currentSession), then RoleChangeService.handleRoleTransition(url)
none change-password, media-configuration, content-editor —

RoleChangeService.isRouteAllowedForRole (URL prefixes allowed per role):

Role Allowed URL prefixes
admin everything
customer_support /home, /issues
event_manager + ticket_manager /program-management, /venue-management, /media-configuration, /content-editor, /events
ticket_manager /home, /events/event-ticket, /events/generate-ticket
ticket_operator /home, /, /events/event-ticket, /report, /events/generate-ticket
event_manager /program-management, /events, /venue-management, /media-configuration, /content-editor

Role-change detection: the role string is compared with sessionStorage.lastKnownUserRole; on a change the program resets to 0, a toast "Your role has been changed…" appears and the user is redirected to the role's default page. The role comes from Amplify user info cached for 55 minutes (X-01).

User portal guards: AuthGuard checks only the local flag localStorage.rvl_cognito_auth == "true"; UnAuthGuard lets the OneID popup through and otherwise redirects signed-in users home; LanguageGuard handles the /:lang segment (P-13).

9. Handover notes

  1. Menus and server rules disagree in places. Examples: ticket_manager sees "Generate Ticket" but the backend reserved-ticket endpoints accept any Admin-pool user (X-14), so customer_support could call them directly; the Site Settings routes (media-configuration, content-editor) have no route guard at all.
  2. The /settings module is routed but not in any menu. It holds notices, landing page, programs, program teams, program venues and footer settings screens (A-31, A-30).
  3. Role string matching. The menu uses roles.includes('admin') on the comma-separated string, which is a substring check: any future role containing "admin" would also match. isRouteAllowedForRole splits the string correctly.
  4. User portal AuthGuard trusts a local flag; the real check happens when the token interceptor or the API rejects the call.
