X-12 Checker login

Bangla name: চেকার লগইন

← 60 · Cross-cutting · Contents · Open queries

1. Name and purpose

Checker login. Gate staff sign in to the checker app with the phone number and password that the admin portal created for them (X-05, A-17). The app uses the TicketChecker Cognito pool. Before signing in it checks that the installed app version is still allowed.

2. Trigger and actor

Item Value
Actor Gate staff (ticket checker)
Client and screen Checker app /splash → /signIn (SignInViewModel.signInUser) → /eventPage
Cognito pool TicketChecker
Role / program scope Backend adds role ticket-checker to every token of this pool (X-14)

3. Business flow

  1. On start the splash screen checks the version and, if a session exists, opens the event page directly.
  2. Otherwise the checker types the phone number (without +880) and password.
  3. The app checks the version again; if an update is required, a blocking "Update required" sheet appears.
  4. On success the event page opens and loads the assigned event and gate (C-01).
  5. "Sign out" is on the event page.

4. Technical flow

# From → To Hop What happens
1 App → identity GET user/allowed-app-version [HTTP, static key] (AuthApiClient, header Authorization: <AUTH_API_TOKEN or empty>) Reads data.tc.android / data.tc.ios (tc = this app; the user app reads up)
2 App → Cognito (TicketChecker pool) Amplify Flutter Amplify.Auth.signIn("+880…", password) If not fully signed in (any challenge), the session is null
3 App → Admin, TicketChecker services [HTTP + user token] (TicketApiClient, Bearer <accessToken> from fetchAuthSession) First call: GET /admin/api/v1/ticket-checker-gate/event-info (C-01)
4 Sign out Amplify.Auth.signOut() from the event page Local

9. Handover notes

  1. Debug builds log the password. AWSAmplifyService.login logs username and password with Logger.debug; logging is enabled only when kDebugMode is true (main.dart). Do not share debug-build logs.
  2. AUTH_API_BASE_URL is not in the required list of the checker app; if it is missing the version check cannot run.
  3. No password change or reset in the app. Checkers get new passwords from an admin ("Set Password" in A-17); the backend also has PUT /admin/api/v1/ticket-checker/change-password (body with the checker's access token), which no client calls.
  4. Disabled accounts: disabling a checker in the admin portal calls AdminUserGlobalSignOut; the app keeps working offline with already downloaded tickets until it next needs the server (C-02).

11. Developer test guide

Local testability: Not locally (sign-in), Partial (backend). Amplify Flutter cannot be pointed at Floci, so the app cannot sign in locally (docs/mobile-local.md §8, known gap 1). The checker's backend calls can be tested with a Floci token.
