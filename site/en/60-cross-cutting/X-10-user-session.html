X-10 Customer change password, logout and token attach

Bangla name: গ্রাহকের পাসওয়ার্ড পরিবর্তন, লগআউট ও টোকেন সংযুক্তি

← 60 · Cross-cutting · Contents · Open queries

1. Name and purpose

Customer session handling. How the user portal and the user app attach the User-pool access token to API calls, what happens when it expires, and how the customer changes the password and logs out. Every customer feature that needs a login relies on this.

2. Trigger and actor

Item Value
Actor Signed-in customer
Client and screen Portal: every HTTP call (TokenInterceptor); profile page → change password (UserProfilePagesComponent); header → Logout (DefaultComponent.signOutUser). App: every call through TicketBanglaApiClient / ProfileApiClient; Profile → change password / sign out (ProfileViewModel)
Cognito pool User

3. Business flow

  • Change password: current password, new password twice; a success message for 7 seconds (portal). The customer stays signed in.
  • Logout: the customer is signed out and lands on the login page (portal) or login screen (app).
  • Expired session: the portal signs the customer out when a call is about to be sent with an expired token.

4. Technical flow

Portal token attach (TokenInterceptor, registered in app.module.ts): the token is added only when the request URL contains one of these prefixes; every other request (for example the public Event endpoints) goes without a token:

URL contains Used by
${services.bookings}/booking booking, capacity, orders (P-04–P-08)
${services.bookings}/admin/api/v1/discount system discount lookup (P-04)
${services.bookings}/admin/api/v1/user-issue legacy issue endpoints (Appendix A)
${services.userissue}/userissue/api/v1/user-issue issues (P-12)
${services.userissue}/userissue/chathub SignalR negotiate
${services.tickets}/ticketing tickets (P-09, P-10)
${services.identity}/user/my-profile, /user/register-sso profile (P-11, X-08)
${services.bookings}/event/api/v1/events/venue-details venue details for the seat map

Steps: Auth.currentSession() (Amplify refreshes with the refresh token when needed) → if the returned token's exp has passed anyway, remove rvl_cognito_auth, clear the profile, sign out and fail the request with a synthetic 401 → otherwise add Authorization: Bearer.

App token attach: TicketBanglaApiClient (base API_BASE_URL) and ProfileApiClient (base AUTH_API_BASE_URL) call Amplify.Auth.fetchAuthSession() before each request and add Bearer <accessToken>; with no session they throw CognitoUserSessionNotFoundException. AuthApiClient uses the static AUTH_API_TOKEN instead.

# Action Calls
CP Change password Portal: Amplify Auth.changePassword(user, old, new). App: Amplify.Auth.updatePassword. Both → Cognito ChangePassword
LO Logout (portal) Auth.signOut({ global: false }); SSO users with skipFederatedLogout (no redirect to Cognito/OneID logout); removes rvl_cognito_auth, SSO flags, profile; navigate to /:lang/auth/login
LO Logout (app) Amplify.Auth.signOut(); local user data cleared; the call that deletes the FCM token is commented out (profile_view_model.dart, // await firebaseRepository.deleteFCMToken();)

6. API contracts

No GoBCB endpoint of its own. Header added: Authorization: Bearer <User-pool access token>. Validation on the server side: X-14.

7. Data and side effects

Cognito password change; local token removal on logout. Device tokens for push stay registered after logout (app), so pushes for that user can still reach the device (X-23).

9. Handover notes

  1. Token attach is an allow-list of URL fragments built from the environment base URLs. A new backend path that needs a token must be added to TokenInterceptor, otherwise calls go without Authorization and get 401.
  2. No retry on 401. The portal never refreshes after a 401 from the server; it relies on Amplify refreshing before the call.
  3. Logout is local. Other sessions and the OneID session stay alive (X-08).
  4. App logout keeps the push token (see §7).
